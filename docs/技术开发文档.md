# 扫码智能记账打印系统 — 技术开发文档

> 版本：v1.3　日期：2026-10-10　状态：开发联调中（变更记录见 §11）

## 1. 项目概述

一套基于微信小程序的扫码收款、记账与蓝牙打印系统：

- 收款方（店主）绑定个人微信收款码，生成系统收款二维码；
- 付款方扫该二维码进入小程序，填写姓名（必填）、金额（必填）、备注（选填）完成账目登记，并跳转微信完成实际转账；
- 收款方可查看全部账目条目与汇总统计；
- 每收到一笔转账，自动通过蓝牙打印机（ESC/POS）打印支付小票；
- 打印排版与格式可在小程序内自定义。

### 1.1 技术选型（已确认）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 微信原生小程序 | WXML/WXSS/JS，蓝牙 API 支持最完整 |
| 后端 | 微信云开发 | 云函数 + 云数据库 + 云存储，免运维 |
| 支付 | 个人收款码模式 | 无需商户资质；预留微信支付商户 API 升级路径 |
| 打印 | BLE 蓝牙 + ESC/POS | 支持芯烨/汉印/佳博等主流 58mm 蓝牙热敏打印机 |

### 1.2 重要边界说明（必读）

1. **资金流**：个人收款码模式下，系统只做**账目登记**，实际转账由付款方在微信内完成（展示收款码 → 长按/截图 → 微信扫一扫转账）。系统不触碰资金，无需商户资质。
2. **蓝牙**：微信小程序仅支持 **BLE（低功耗蓝牙）**。主流便携热敏打印机（芯烨 58/80 系列、汉印 HM/MT、佳博 PT 系列）均支持 BLE。经典蓝牙 SPP 打印机不在支持范围。
3. **升级路径**：若后续申请到微信支付商户号，可将 `payment` 云函数切换为 `wx.cloud.callFunction` → 微信支付下单 API（`cloudPay` / 统一下单），二维码变为真实支付码，支付回调自动落账，架构已预留该分支（见 §6.4）。

## 2. 角色与用例

| 角色 | 用例 |
|---|---|
| 收款方（注册用户） | UC1 登录注册；UC2 绑定收款账户并上传收款码；UC3 生成/分享收款二维码；UC4 设置记账主题；UC5 查看账目列表与汇总；UC6 连接蓝牙打印机；UC7 自定义打印格式；UC8 打印小票 |
| 付款方（任意微信用户） | UC9 扫收款二维码 → 填写姓名/金额/备注 → 确认登记 → 获取收款码完成转账 |

## 4. 数据模型（云数据库）

### 4.1 users — 用户表
```json
{
  "_id": "自动",
  "openid": "oXXXX（唯一索引）",
  "nickname": "张三",
  "avatar": "头像 URL",
  "createdAt": "Date",
  "lastLoginAt": "Date"
}
```

### 4.2 accounts — 收款账户表（每个用户一个）
```json
{
  "_id": "aid（自动）",
  "ownerOpenid": "oXXXX（唯一索引，一户一码）",
  "accountName": "店铺收款账户",
  "payCodeFileID": "cloud://…（个人微信收款码图片的云存储 fileID）",
  "theme": { "name": "默认主题", "primary": "#07C160", "bg": "#F7F7F7" },
  "createdAt": "Date",
  "updatedAt": "Date"
}
```

### 4.3 records — 账目表
```json
{
  "_id": "rid",
  "aid": "收款账户 _id（索引）",
  "ownerOpenid": "oXXXX（索引，收款方查询用）",
  "payerName": "付款人姓名（必填）",
  "amount": 88.5,               // Number，单位元，两位小数
  "remark": "备注（可空）",
  "status": "paid",             // paid | void（作废）
  "printed": false,             // 是否已打印
  "payDay": "2026-10-10",       // 冗余日字符串，便于按日汇总
  "createdAt": "Date"
}
```

### 4.4 print_templates — 打印模板表（每个用户一套）
```json
{
  "_id": "自动",
  "ownerOpenid": "oXXXX（唯一索引）",
  "name": "小票模板",
  "paperWidth": 32,             // 58mm≈32 字符/行
  "fields": ["title","aid","payDay","time","payerName","amount","remark","thanks"],
  "title": "收款凭证",
  "fontSize": "normal",         // normal | double（金额双倍字号）
  "showDivider": true,
  "alignAmount": "right",
  "thanks": "谢谢惠顾",
  "updatedAt": "Date"
}
```

### 4.5 数据库权限
全部集合权限设为 **仅创建者可读写**；所有跨用户读写（付款方写 records、读 accounts）一律走**云函数**（云函数持有管理员权限），前端不得直连数据库跨集合查询。

## 5. 云函数设计

统一出入参协议：`{ code: 0, msg: 'ok', data: … }`，`code≠0` 为业务错误。

| 云函数 | action | 入参 | 出参 data | 说明 |
|---|---|---|---|---|
| `login` | `login` | userInfo{nickname,avatar} | {openid,user,isNew} | openid 落库注册/更新 |
| `account` | `get` | – | {account} | 取当前用户收款账户，无则返回空 |
| | `save` | {accountName,payCodeFileID,theme} | {account} | 建/改账户，收款码图片转存 |
| | `getByAid` | {aid} | {account(脱敏)} | 付款方扫码后取账户公开信息 |
| `payment` | `create` | {aid,payerName,amount,remark} | {record} | 校验必填→写 records→返回账目 |
| | `void` | {rid} | – | 收款方作废账目 |
| `records` | `list` | {page,pageSize,dateRange?,keyword?} | {list,total,sum} | 分页+汇总 |
| | `detail` | {rid} | {record} | 单条 |
| `printtpl` | `get` | – | {tpl} | 取打印模板，无则默认 |
| | `save` | {tpl} | {tpl} | 保存 |
| `qrcode` | `gen` | {aid} | {fileID} | 生成含 aid 的系统收款二维码（小程序码，scene=aid） |

> 二维码方案：调用微信 `openapi.wxacode.getUnlimited`（云函数内免鉴权）生成小程序码，`scene=aid=xxx`，付款方扫码进入 `pages/pay/pay`，解析 scene 得 aid。

## 6. 关键流程

### 6.1 登录注册
```
wx.getUserProfile（可选昵称头像）→ callFunction('login',{userInfo})
→ 云函数取 OPENID → users upsert → 返回 user → 本地存 openid
```

### 6.2 绑定收款账户（UC2）
1. `account.save`：上传收款码图片至云存储 `paycodes/`（`wx.cloud.uploadFile`）；
2. 云函数转存校验（≤2MB，image/*），upsert accounts；
3. `qrcode.gen` 生成系统收款小程序码存 `qrcodes/`，返回 fileID。

### 6.3 扫码付款（UC9，核心）— v1.1 转账确认流程
```
付款方「扫码付款」扫收款方小程序码 → pages/pay/pay 解析 aid
① 填写：姓名(必填) 金额(必填) 备注(选填) → 点「确认转账」
   → payment.create 写入 records(status=pending)，返回收款码
② 转账：长按识别收款码完成微信转账 → 点「我已完成转账」
   → payment.transferred (status=transferred)
③ 确认：付款方页面"等待收款方确认…"，每 3s 轮询 payment.status
   收款方账目页（每 5s 自动刷新，有新转账震动提醒）核对微信到账 → 点「确认收款」
   → payment.confirm (status=paid) → 收款方端自动蓝牙打印小票
④ 付款方页面自动变为「转账成功，已登记」；若收款方点「未收到」→ status=rejected，付款方显示失败
```
状态机：`pending → transferred → paid → void`；`pending → cancelled`；`transferred → rejected`。
汇总金额只统计 `paid`。个人收款码无到账接口，故以收款方确认作为"转账成功"判定；接入微信支付商户后由支付回调自动置 `paid`（见 §6.4）。
**打印触发**：收款方打开小程序/`records` 页时，拉取 `printed=false` 的账目，逐条提示打印；打印成功后回写 `printed=true`。V1 采用"打开即提示打印"的拉模式（可靠、省电），不采用小程序后台推送（不可行）。

### 6.4 微信支付商户升级路径（预留）
`payment.create` 内已抽离 `gateway` 层。切换商户模式时：新增 `cloudPay` 分支 —— `getByAid` 改返回统一下单 `payment` 参数，前端 `wx.requestPayment`，回调云函数落账。records 增加 `wxTransactionId` 字段即可，其余模型不变。

### 6.5 蓝牙打印（UC6/UC8）
```
wx.openBluetoothAdapter
→ startBluetoothDevicesDiscovery（按名称/广播过滤打印机前缀：Print/Xprinter/HM/GB/HPRT…）
→ wx.createBLEConnection(deviceId)
→ 获取 service 0000FF00-…（芯烨等通用）下特征值 0000FF02（可写+notify）
→ escpos.js 构造字节（init→文本(GBK 编码)→对齐/字号指令→切纸）
→ 分包(≤20B/包) wx.writeBLECharacteristicValue 循环写入
→ 打印完成回写 records.printed=true
```
**编码**：中文用 GBK（`text-encoding` polyfill 或内置 GBK 映射表 `gbk.js`）。打印机不支持 UTF-8，必须 GBK。
**排版**：58mm 纸 384 点宽 ≈ 32 英文字符/16 汉字一行；模板字段按 `fields` 顺序输出，金额可设双倍字号右对齐。

### 6.6 打印格式自定义（UC7）
`printset` 页：模板名称、纸宽(32/48)、字段开关与排序（长按拖动）、标题文字、金额字号、分隔线、致谢语 —— 实时预览区（WXML 模拟小票）→ `printtpl.save`。

### 6.7 账目导出（PDF / Excel）
云函数 `export`（timeout 60s）：按 `ownerOpenid + status=paid + payDay 区间 (+themeName)` 分批拉取（≤5000 条）→
- PDF：pdfkit + 内嵌思源黑体子集（GB2312 7574 字，1.7MB，SIL OFL 协议），A4 表格、自动分页、表头重复、合计行、页码；
- Excel：exceljs，标题/区间/冻结表头/金额格式/SUM 公式合计；
→ 上传云存储 `exports/{openid}/` → 前端 `wx.cloud.downloadFile` + `saveFile`（可读文件名）→ `wx.openDocument({showMenu:true})` 预览，可转发好友或文件传输助手存档。

## 8. 非功能需求

- **安全**：云函数侧校验 openid 归属；金额用 `Number` 两位小数、服务端二次校验；付款方只能 `create`，不能读他人 records。
- **金额精度**：全程浮点元，存储两位小数，汇总用整数分计算后还原（`Math.round(sum*100)/100`）避免浮点误差。
- **性能**：records 分页 20 条/页；云函数冷启动首包 <2s 可接受。
- **体验**：打印失败自动重试 1 次；BLE 断连自动提示重连。
