# 慧礼记 — 提审与隐私配置说明

## 一、提审建议

**服务类目**：工具 > 记账（或 工具 > 备忘录）。不要选金融、支付类类目。

**版本描述（可直接粘贴）**

> 慧礼记是一款礼金记账工具，帮助用户记录婚礼、寿宴、满月、乔迁、白事等场合的礼尚往来，生成电子礼簿、回执和往来统计，方便日后查询与回礼。
> 小程序本身不提供任何支付、收款或资金托管功能：宾客在小程序内只登记姓名与礼金金额，实际转账由宾客使用微信「扫一扫」向主家本人的微信收款码完成，资金直接进入主家本人的微信零钱，小程序不经手、不留存任何资金。主家确认收到后，系统才把该笔礼金记入礼簿。

**审核备注（填写在"补充说明"）**

> 1. 测试路径：「我的」登录 →「主家信息」上传任意收款码图片 →「礼簿管理」新建礼簿 → 工作台「出示礼簿码」→ **请用第二个微信扫这个礼簿码**，以宾客身份登记一笔（可选「现金」，无需真实转账）→ 回到主家微信，工作台「待确认」点「确认收到」→ 查看电子回执、礼簿统计、往来、导出。（「模拟宾客随礼」入口只在开发版 / 体验版显示，审核版请用第二个微信扫码。）
> 2. 收款码为主家本人上传的个人微信收款码，仅在主家自己的礼簿页面向其宾客展示，用于宾客自愿转账随礼；小程序不发起支付、不代收款、不分账。
> 3. 蓝牙权限仅用于连接主家自备的热敏打印机打印礼金回执。

**可能被问到的问题**

| 问题 | 回答要点 |
|---|---|
| 是否涉及资金交易 | 否，小程序只做登记；转账在微信内由用户自行完成 |
| 是否诱导转账 | 否，转账对象为主家本人，金额由宾客自行决定，可不转账直接取消 |
| 收款码来源 | 主家本人上传，仅主家本人礼簿使用 |

若仍被拒，长期方案为接入微信支付商户号（技术文档 §6.4 方案 A），由微信支付回调确认到账。

## 二、用户隐私保护指引（小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引）

需勾选并填写用途：

| 信息类型 | 用途说明（可直接粘贴） |
|---|---|
| 微信昵称、头像 | 用于主家登录后显示个人信息 |
| 选中的照片或视频信息 | 用于主家上传本人微信收款码图片、礼簿封面照片（v3.84.2 补封面照片） |
| 相册（仅写入）权限 | 用于保存礼簿码、礼簿台卡、电子回执、对账图片、主家收款码到手机相册 |
| 蓝牙 | 用于连接热敏打印机打印礼金回执 |
| 摄像头 | 用于扫描礼簿码（wx.scanCode），以及上传收款码、封面照片时选择「拍摄」 |
| 剪切板（写入） | 用于点「复制」时写入礼簿编号、对账文字，不读取剪切板内容 |
| 头像上传 | 头像上传到微信云存储，用于在账号与相关礼簿中显示（v3.67.2 起） |
| 用户输入的信息（姓名、金额、关系、祝福语） | 用于生成礼簿、电子回执和人情往来统计；主家及其授权的记账人（礼台人员）、家人可见，宾客本人可查看自己的记录 |

**小票二维码与认领（v3.57.0 起，v3.58.0 改为小程序码）**：热敏小票底部可打印一个小程序码（v3.59.0 起默认关闭，主家在打印设置里自行打开），用微信扫码打开这一笔随礼的电子回执。
- 小程序码里只有 `t=` 加一个 12 位随机字符串（不含姓名、金额等内容），指向「电子回执」页；小程序码永久有效，任何人扫到都能打开这一笔回执（姓名、关系、金额、备注、主家称呼），不含其他礼金或礼簿信息。主家可在「礼簿 → 更多 → 重置二维码」换掉随机字符串，旧小票上的码立即失效。
- 为加快补打，云端会把小程序码图片转成打印数据，按这笔记录缓存到云存储（`rcptqr/` 目录，仅云函数可访问，文件里只有黑白点阵）；缓存按小程序版本（正式版 / 体验版）区分，每条记录只留一份；重置二维码时删除旧缓存，主家清除数据时一并删除。
- 礼台代为登记的记录没有宾客的微信身份。宾客扫码后可点「放入我的随礼记录」认领：仅在这笔记录无人认领时有效，先认先得，只记录认领人的微信标识用于在其「我的随礼记录」中显示，不改动主家的账目；主家可「解除认领」。宾客清除自己的数据时，其认领会被解除（记录属于主家，不删除）。
- 隐私指引「用户输入的信息」用途可补充：「用于生成电子回执及小票小程序码，扫码查看回执与放入我的随礼记录」。无需新增权限类别。

**内容安全（v3.71.0 起）**：用户填写、会展示给他人的文字与图片，在云端提交时调用微信官方内容安全接口检测，违规内容提示「内容含有不适宜信息，请修改后再提交」，不保存、不展示。
- 文字（`security.msgSecCheck` v2）：礼簿名、礼簿地点、主家称呼、机构名称、本场主家称呼、记账人姓名、回执标题 / 落款 / 页脚、小票标题 / 致谢语 / 页脚、微信昵称、宾客填写的姓名 / 备注 / 区分备注，以及礼台录入的随礼人姓名 / 备注。仅本人可见的往来记录不送审。
- 图片（`security.imgSecCheck`）：收款码图片、本场收款码、头像；超过 1MB 的图片接口不支持，跳过检测。
- 送审内容只用于检测，开发者不另行保存；检测服务异常、超时或未开通权限时不阻断用户操作。
- 提审说明可补充：「小程序对用户输入的文字与图片接入微信内容安全接口」。无需新增隐私权限类别。

**订阅消息（微信服务通知）**：均为一次性订阅，用户点「允许」才发送，每次允许只发一条，不用于营销。
- 新礼金提醒（给主家 / 记账人）：宾客点「我已完成转账」后提醒核对确认；模板 ID 见 `miniprogram/config.js` 的 `NOTIFY_TMPL_ID`（v3.77.1 换新模板，字段：thing1 主家+礼簿事由 / thing4 随礼人姓名（批次「张三等3人」）/ amount7 金额 / time9 时间 / thing3 提醒事由，白事用「奠仪待确认」；之前订阅旧模板的用户需重新开启一次）。**v3.66.3 起默认关闭**，主家 / 记账人在「我的 → 高级功能 → 新礼金微信提醒」自行开启（开启时才弹订阅授权），未开启的人不会弹授权、不会收到提醒。
- 入簿通知（给宾客，v3.66.1）：宾客在随礼时（「我已完成转账」或现金「确认随礼」）允许后，主家确认收到时发一条，内容为主家称呼与事由、金额、记账时间、支付方式、备注，点开查看这一笔的电子回执；礼台代为登记的宾客没有微信身份，不发送。模板 ID 见 `GUEST_NOTIFY_TMPL_ID`。
- 未收到 / 核对结果通知（给宾客，v3.77.0）：与入簿通知同一次授权弹窗里一并请求（两个模板额度互不占用）；主家核对后标记「未收到」、或宾客申诉后主家「维持未收到」时发一条，内容为主家称呼与事由、记账时间、金额、备注（白事措辞为「暂未核实到账」），点开进入「我的随礼记录」；模板 ID 见 `GUEST_REJECT_TMPL_ID`（云端常量在 `tools/cloud-shared/guestnotify.js`）。
- 记录变更通知（给宾客，v3.85.0）：复用「记账提醒」模板（`GUEST_REJECT_TMPL_ID`，与未收到通知共用同一次授权的一次性额度）；主家 / 记账人修改（金额、姓名）或作废宾客的记录，由 warmer 在 10 分钟后合并发一条（内容为主家称呼与事由、金额、时间、「记录已更正 / 已作废」）；主家发起更正申请时立即发一条「申请更正，请到小程序确认」。宾客可在回执页、「我的随礼记录」点「开启变更提醒」再次授权（只订阅这一个模板）。没有额度、礼台代登记的宾客不发，仍可在「我的随礼记录」里看到。
- 亲友办事提醒：用户自己设置提醒时允许，到期提醒；模板 ID 见 `REMIND_TMPL_ID`。
- 小程序内「隐私与数据」页有对应的「微信服务通知」一节，改这里时同步修改 `pages/privacy/privacy.js`。

**联系客服与反馈**：用户主动联系客服、提交反馈时提供的信息（文字、截图及微信自带的机型 / 版本信息）由微信客服 / 反馈通道处理，开发者仅用于答复和定位问题，小程序自身不另行收集。

**数据保存与删除**：数据存储于微信云开发；导出文件在下载后立即从云端删除，未下载的导出文件 24 小时内自动清理；主家可在「我的 → 隐私与数据 → 清除我的全部数据」永久删除全部数据。主家删除礼簿（回收站）或自己清除数据 / 注销时，宾客的随礼记录不会随之消失（见下）。

**72 小时修改规则与更正申请（v3.85.0）**：已入簿的礼金，主家 / 记账人只能在确认收到（paidAt）后 72 小时内直接修改或作废，不顺延（申诉后入簿重新计时）；超过 72 小时只能发起「更正申请」（改金额 / 改姓名 / 作废 + 理由，理由经内容安全检测），经随礼人在「我的随礼记录」同意后才生效，拒绝或 7 天未处理（warmer 自动置过期）保持原样；每笔最多申请 3 次；只有有随礼人身份（扫码登记，或扫小票二维码放入记录）的记录才能申请。修改与作废写入日志，随礼人可见。v3.85.0 之前入簿的老记录，给到上线后 72 小时的缓冲。

**宾客随礼凭证（v3.85.0）**：随礼人（有 openid 身份的宾客）在主家的礼簿里的记录，原本只存在主家的礼簿中。主家删除礼簿（移入回收站前）、或主家自己清除数据 / 注销（删除记录前），系统为这些随礼人各保留一份凭证到集合 `guest_receipts`（保存在随礼人自己名下）：只含主家称呼、礼簿名、日期、金额、状态（已入簿 / 已作废 / 未收到）和修改记录；不含记账人、收款码、备注、关系和任何主家内部标识。凭证长期保留，直到随礼人自己在「我的随礼记录」里删除；随礼人自己清除全部数据时一并删除；回收站恢复礼簿后以实时记录为准、凭证删除；用户自己删簿 / 注销不会删除凭证。管理员「清除测试数据 / 清除用户 / 清除单本礼簿」会连同这些凭证一并删除。没有随礼人身份的现金礼台记录不保留。

**后台「用户隐私保护指引」需要同步补充的内容（提交审核前在小程序后台修改）**：
1. 「开发者处理的信息」里，在随礼人姓名、金额等信息的说明中补充：主家删除礼簿或注销后，为随礼人保留一份凭证（仅含主家称呼、礼簿名、日期、金额、状态、修改记录），长期保留，随礼人可随时自行删除。
2. 「信息保存期限 / 删除方式」处补充：用户自己的数据可在「我的 → 隐私与数据」清除；随礼凭证由随礼人本人在「我的随礼记录」删除。
3. 「订阅消息」说明补充：主家修改 / 作废 / 申请更正时，向随礼人发送「记账提醒」类服务通知（用户点「允许」才发送，一次一条）。
4. 说明修改规则：已入簿礼金 72 小时内可修改作废，超期需随礼人同意。
5. 措辞避免默认视同授权类的表述，保持「点击允许才会发送」「由你自行决定」的写法。

**小程序内的隐私说明**：「我的 → 隐私与数据」页（v3.52.0 起，原为弹窗）完整展示：保存的信息、可见范围、导出文件与存档 PDF 的保留、回收站 15 天（会员可选 30 / 60 天）、设备权限（相册写入 / 蓝牙 / 选图 / 摄像头扫码 / 剪贴板）、头像与内容安全检测（v3.71.1 补充）、礼金修改与随礼凭证（v3.85.0）、客服与反馈；未登录也可查看。登录后页面下方为「我的数据」：导出与备份入口、清除我的全部数据。正文与上文保持一致，改隐私指引时同步修改 `pages/privacy/privacy.js` 的 `SECTIONS`。

2. **定时触发器（只有 2 个）**：命令行部署不会上传触发器，在开发者工具里右键 `cloudfunctions/<函数名>/config.json` →「上传触发器」。

3. **云函数超时与内存（必做）**：命令行部署不会应用 `config.json` 的超时，新函数默认 3 秒。云开发控制台 → 云函数 → 选中函数 → 版本与配置 → 编辑：

   | 云函数 | 超时 | 内存 |
   |---|---|---|
   | account、system、warmer、export、fontsetup | 60 秒 | export **1024MB**，其余默认 |
   | payment、records、books、renqing、qrcode | 20 秒 | 默认 |
   | login、init | 10 秒 | 默认 |

   export 内存不足或超时会导致传统礼簿 PDF 生成失败。

3.1 **云调用权限**（云函数 → 选中函数 → 权限配置 → 云调用；命令行部署不一定应用 `config.json` 的 `permissions.openapi`）：

   | 云函数 | 需开启 |
   |---|---|
   | account、books、login | `security.msgSecCheck`、`security.imgSecCheck` |
   | payment | `security.msgSecCheck`、`security.imgSecCheck`、`subscribeMessage.send`、`wxacode.getUnlimited` |
   | qrcode | `wxacode.getUnlimited` |
   | warmer | `subscribeMessage.send` |

4. **数据库权限**：19 个集合全部设为「所有用户不可读写」，前端只通过云函数访问（云函数另外忽略带 `_openid` 的客户端伪造文档）：users、accounts、records、print_templates、books、gifts_out、exports、members、invites、settings、subscriptions、reminders、person_alias、admin_logs、book_codes、trash_books、trash_records、rate_limits、sys_config（存往来人标识密钥，尤其不能放开）。管理员页上线前检查会在手机上逐个试读，能读到的会标红。

4.1 **云存储权限**：保持「所有用户可读，仅创建者可读写」（收款码、头像、导出文件由前端上传，宾客端通过云函数换临时链接）。

5. **环境变量**：system 配置 `WX_APPSECRET`（只在云函数里用，不写进代码）。**不要**给 renqing 设置 `PERSON_KEY_SECRET`：密钥已自动生成在 sys_config，再设环境变量会让已存的往来人标识全部失配。
